> ### 중요 1. 잔액 값이 JSON 문자열이라는 사실이 조사·요구사항·테스트에 없음 (task.md:12, 44, 88~90 / REQ-01~03)
>
> - 근거
>   - `JacksonConfig.java:18,31`이 모든 BigDecimal을 문자열로 씁니다. 실제 응답은 `"availableBalance": "100000000.00"`입니다.
>   - 프론트 타입 `types/api.ts:680,809`는 `number`라고 적어 헷갈리기 쉽습니다.
>   - REQ-03의 "숫자가 아님"은 JSON 타입으로도 읽힙니다.
> - 영향
>   - 가짜 응답을 숫자로 만들면 시나리오가 모두 통과해도 운영에서는 다르게 동작합니다.
>   - jq는 문자열을 숫자보다 항상 크다고 봅니다. `.availableBalance >= 100000000`으로 구현하면 `"0.00"`도 통과해, 1차 실행과 같은 사고가 그대로 재발합니다.
>   - 반대로 숫자 타입만 받으면 운영에서 항상 막힙니다.
>   - Bash 정수 비교는 `99999999.99`에서 오류가 납니다.
> - 수정
>   - 조사 사실과 REQ-03에 "응답은 문자열 십진수이고, 십진수로 해석되지 않는 값(없음, null, 빈 문자열, 문자)이면 중단"이라고 적으세요.
>   - 테스트의 가짜 응답은 실제와 같은 문자열(`"100000000.00"`, `"99999999.99"`, `"0.00"`)로 정하세요.
