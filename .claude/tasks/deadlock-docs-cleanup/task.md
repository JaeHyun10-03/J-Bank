# 작업 명세

## 요구사항 구체화

명세 상태: 확정
원문 요청: 문서 정리
(앞선 대화) 교착 실험 작업의 후속 목록 중 1번이다. 실험 runbook의 18시·14시 표현, 설계 문서 05·06·07의 틀린 CORS 설명, 보고서와 개발일지의 작은 문구, 실행 스크립트에 시작 전 잔액 확인 추가.
요청 해석: 교착 실험에서 드러난 문서의 틀린 서술과 낡은 시각을 바로잡고, 1차 운영 실행(잔액 0원)이 "완료"로 끝난 원인인 실행 스크립트의 시작 전 잔액 확인 누락을 메운다.
조사한 사실:
- 중지 스케줄은 2026-11-25에 매일 00시로 바뀌었다(ADR 0015, PR #20). `docs/runbook/transfer-deadlock-experiment.md`의 87행(14시 전 시작), 122·124행(18시를 넘길 때, 17:40), 141행(18시 자동 종료), 162행(18시 전)이 18시 기준으로 남아 있다.
- 실측: 운영 2차 실험은 15:22~15:55(약 33분), FDS 수동 실행은 1,393초(약 23분)다.
- `perf/run-deadlock.sh`의 `prod-all`은 로그인과 계좌 조회 뒤 곧바로 회차를 시작한다. 잔액을 보지 않는다. 계좌 목록 API(`/customers/{id}/accounts`) 응답에 `balance`·`availableBalance`가 있다. 이체 판정(`TransferService` 104행)에 쓰는 값은 사용 가능 잔액(잔액 − 지급정지)이다. API 응답의 금액은 `JacksonConfig`가 BigDecimal을 문자열로 쓰므로 `"100000000.00"` 같은 **문자열 십진수**다(프론트 타입은 number라고 적혀 있으나 실제는 문자열). jq는 문자열을 숫자보다 크다고 보므로 변환 없이 비교하면 `"0.00"`도 통과한다. 이 API의 설명(Controller 41~42행)은 availableBalance가 항상 0이라고 적지만 실제 값은 정상이다(설명 정정은 앱 코드라 후속 후보).
- 설계 문서 05(131행), 06(54행), 07(163·307행)은 프록시 덕분에 CORS가 필요 없거나 발생하지 않는다고 적는다. 브라우저 기준으로는 같은 출처라 브라우저의 CORS 검사는 없다. 그러나 프록시가 브라우저의 `Origin`을 API에 그대로 넘겨 API의 CORS 허용 목록 검사를 받는다(PR #19, `SecurityConfig` 주석, `perf/results/deadlock/prod/cors-check.md`).
- 07 문서는 v2.3에서 W6~W7 인프라 서술을 "실행된 역사로 남기고 본문을 고치지 않는다"고 적었다. 163행(W3)·307행(프론트)은 그 원칙의 직접 대상은 아니지만, 계획 문서의 원문을 남기고 정정 문장을 덧붙이는 같은 방식을 준용한다(사용자 선택이 필요한 제품 동작 변화가 아님).
- 05 문서 131행에는 CORS 단정이 두 문장에 있다. SameSite를 이유로 든 설계 선택 자체는 맞고 CORS 부분만 틀렸다.
- 저장소 `perf/results/deadlock/prod/`에는 6회의 결과가 있다. 그대로 `prod-all`을 다시 실행하면 6회를 모두 건너뛰고 마지막 설정 복귀(api 재생성)만 한다. 1차 실행 때 결과를 다른 폴더로 옮겨야 했다.
- 결과 리뷰 4회차의 권고 3(REQ-05 e)·4(REQ-05 a)·5(REQ-07)·7(REQ-05 b·c·d)은 snapshot 때문에 미뤄 두었다(`.claude/tasks/transfer-deadlock-experiment/review.md` 4회차 처리).
질문하지 않은 이유: 동작이 갈리는 잔액 검사 방식과 시각 기준은 Q-01·Q-02로 물었다. 문서 문구는 사실 정정이라 묻지 않았다.

원문 요청의 첫 줄은 콜론 뒤에 적고, 길면 이어지는 줄에 계속 적는다. 개인정보·비밀값은 문서에 복사하지 않고 위치와 필요한 의미만 남긴다.

## 목표

다음에 같은 실험을 다시 할 때 잔액이 부족한 계좌로 시작하지 않게 하고, 실험·설계 문서가 현재 운영과 사실에 맞게 한다.

## 범위

- `perf/run-deadlock.sh`의 `prod-all` 시작 전 잔액 확인
- `docs/runbook/transfer-deadlock-experiment.md`의 시각 기준과 사용자 준비 절차
- 설계 문서 05·06·07의 CORS 서술
- 교착 실험 보고서·확인 기록·개발일지의 문구(아래 REQ-05)

## 완료 기준

1. REQ-01~04: 임시 폴더에 복사한 스크립트와 가짜 명령으로 돌린 시나리오가 모두 기대와 같고(아래 일반 테스트 방법), `bash -n`·`shellcheck`(변경 전보다 새 경고 0)와 `verify`가 통과한다. 시나리오 스크립트 전문은 `logs/balance-check.md`에 남긴다.
2. REQ-05: (a)~(e)가 모두 고쳐졌고, cors-check 표의 값이 `logs/cors-output.md`와 같으며, 두 환경의 `deadlock-summary.py --check`가 계속 일치한다.
3. REQ-06: 세 문서에 같은 취지의 정정이 있고, 남은 "CORS가 필요 없다/발생하지 않는다" 서술이 정정 문장 없이 남지 않는다.
4. REQ-07: runbook에서 `18시|17:40|14시` 검색이 0건이고(과거 기록이 아닌 절차 문장), REQ-07의 항목이 모두 있다.
5. 비밀번호·토큰·메일 주소·계좌번호·전화번호가 커밋 파일에 없다.

- 프론트: 해당 없음. 화면 변경 없음.

- 전체 흐름: 해당 없음. 사용자 화면 흐름 변경 없음.

프론트·백엔드·전체 사용자 흐름 중 해당 대상을 정한다. 정상·실패·경계값·권한·동시 요청을 검토하고, 제외한 항목은 이유를 기록한다.
작업 완료에 필요한 테스트와 배포 전·후 및 정기 점검을 구분한다.

- 권한·동시 요청: 해당 없음. 로그인 흐름과 동시성은 바꾸지 않는다.
- 운영에서의 검증은 하지 않는다(실험 재실행은 범위 밖). 다음 운영 실험에서 처음 쓰인다.

## 성능 테스트

- 필요 여부와 이유: 불필요. 시작 전 조회 1회를 더하는 스크립트와 문서 변경이다.

## 추가 맥락

- 잔액은 `balance`가 아니라 `availableBalance`(사용 가능 잔액)로 본다. 지급정지가 있으면 이체에 쓸 수 없기 때문이다.
- 새 시작의 기준 금액(1억 원)은 교착 실험의 고정 조건(`docs/runbook/transfer-deadlock-experiment.md`, PERF-01)과 같다.
- 실험용 계좌 준비: 화면 홈에는 계좌가 있으면 개설 버튼이 없다(`apps/frontend/app/page.tsx` 223행). 가입 로그인 ID는 휴대폰 번호다.
- 시나리오 실행 조건(REQ-01~04): `perf/run-deadlock.sh`를 `<임시>/perf/run-deadlock.sh`로 복사한다(`ROOT`가 스크립트 폴더의 상위라 임시 폴더 아래에 결과가 생기고 저장소 결과를 건드리지 않음). `prod/` 결과는 빈 상태로 시작하고, `BASE_URL=http://127.0.0.1:<닫힌 포트>`, 가짜 `INSTANCE_ID`, 가짜 AWS 자격증명 환경변수를 쓴다. 가짜 계좌 응답은 문자열 금액의 ACTIVE 계좌 3개(ID 순서를 섞음, 예: 10·9·11)이고 세 번째 계좌에 큰 잔액을 두며 `balance`는 `availableBalance`와 다른 값으로 둔다. `curl`·`aws`·`docker`·`k6`를 가짜로 PATH 앞에 둔다(호출 인자를 기록, `curl`은 `-D`·`-o`·`-w`·`--data-binary @-`를 실제처럼 처리). 실행 전후 저장소 `perf/results`의 `git status`가 같은지 기록한다. 가짜 값에는 SEC-05 패턴에 걸리는 계좌번호·휴대폰 번호를 쓰지 않는다.
- SEC-05 대상 명령: `git diff -z --name-only --diff-filter=d origin/main...HEAD` + `git diff -z --name-only --diff-filter=d HEAD` + `git ls-files -z --others --exclude-standard -- perf/run-deadlock.sh perf/results/deadlock docs .claude/tasks/deadlock-docs-cleanup`(중복 제거 후 `xargs -0 grep -nE`). 패턴: `eyJ[A-Za-z0-9_-]{20,}\.|(XSRF-TOKEN|access_token)=[A-Za-z0-9._-]{16,}|[A-Za-z0-9._%+-]+@gmail\.com|110-[0-9]{6}-[0-9]`, `(^|[^0-9])010[0-9]{8}([^0-9]|$)`. 대상에서 `docs/planning`(이 작업 파일 아님)은 나오지만 커밋하지 않는다.
