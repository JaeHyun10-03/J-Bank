# EC2 부하 테스트 개선 전 기준선 — 회차별 결과 (재측정)

측정일 2026-09-28(KST). 조건은 `.claude/tasks/ec2-load-test/task.md`의 "측정 조건"(Q-07 반영), 절차는 `perf/README.md`의
"EC2 부하 테스트" 절. 원인 분석은 [bottleneck-analysis.md](bottleneck-analysis.md). 1차 측정(지표 공백·재로그인 동시 몰림·
실패 반영 수치 혼입 결함이 있던 기록)은 [first-pass/](first-pass/)에 보존하고, 기준선 수치는 이 재측정만 쓴다.

- 대상: t3.small(2 vCPU·2GB, 크레딧 unlimited), api 이미지 `490ed107…`, JVM `-Xmx512m`, Hikari 10·Tomcat 200(기본값). 관리 엔드포인트는 별도 포트 9095. 환경 기록: [env/](env/).
- 부하 발생기: c7i.large(전 회차 같은 유형). 회차별 발생기 CPU 최대 27% 이하.
- 무효 회차 없음: 모든 회차 `gaps.txt` invalid=no(수집 대상 6개 모두 15초 초과 결측 0), 발생기 CPU 80% 이하, S5 KST 자정 넘김 없음. 추가 측정 없음(S1·S2·S3·S5 각 3회, S2 변동폭 한 단계 이내).
- 무너짐 기준: 단계 구간 p95 > 200ms, 오류율 > 1%, 컨테이너 재시작·OOM. 단계 시작 후 10초 제외. p95·오류율은 k6(클라이언트) 기준.
- 정합성(모든 회차): 새 원장 행 = 2 × 새 이체, 새 원장 차변 합 = 대변 합, 기준 대사 대비 새 불일치 계좌 0, 경계 이후 멱등키 중복 0, 정합성 확인용 대사 잡 성공. S2는 핫 계좌 잔액 증가분 = 성공 이체 금액 합(DB).
- "실패 응답인데 반영"은 k6가 남긴 실패 이체 멱등키를 DB와 대조한 값이다. k6를 SIGINT로 멈춘 S1·S2는 끊긴 요청의 키도 남으므로(키 수 > 체크 실패 수), 실제 실패 응답 중 반영의 하한은 "반영된 키 − (키 수 − 체크 실패 수)"다. 키가 없는 잔차(새 완료 − 201 − 반영된 키)는 중단 순간 처리 중이던 요청이다.
