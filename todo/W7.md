## 쿠버네티스 배포 (Helm)

- [x] Helm 차트 작성 — API 디플로이먼트 + 배치 CronJob을 한 차트에,
      두 워크로드가 같은 이미지 태그를 참조하도록 값 파일 구성
- [x] 환경별 값 파일 분리(dev/prod)
- [x] readiness probe(DB 연결까지 확인)와 liveness probe(프로세스만
      확인) 분리 — 같은 엔드포인트로 두면 DB 지연만으로 컨테이너가
      통째로 재시작되는 사고가 남
- [x] 롤링 업데이트에 종료 유예 시간(terminationGracePeriodSeconds)과
      파드 중단 예산(PodDisruptionBudget) 설정
- [x] 무중단 배포 검증 — 배포 중 k6 부하 스크립트 실행, 실패 요청
      0건 확인(이번 주 완료 기준의 절반) — 실제 EKS 클러스터, 4502건
      요청 중 실패 0건(`perf/results/2026-08-31-w7-rolling-update.log`)

## 서비스 분리(상품·계약 도메인)

> 진행 방식: 전면 MSA 전환이 아니라 분리가 정당화되는 경계 하나만
> 실제로 떼어낸다. 상품/계약 도메인이 대상 — 거래 코어와 트랜잭션
> 경계를 공유할 필요가 없고 배포 주기도 다름.

- [x] `product` 패키지를 별도 모듈로 승격 → 독립 배포 단위로 분리
      (`apps/jbank-product`, 별도 Gradle 프로젝트·별도 Deployment 예정)
- [x] W1부터 ArchUnit이 막아온 역방향 의존이 실제로 없었는지 분리
      과정에서 검증, 결과를 ADR에 기록(경계가 실제로 값을 했는지) —
      이자 배치 잡의 역방향 의존을 실제로 발견·해소함
      (`docs/adr/0007-w7-product-module-separation.md`)
- [x] 상품가입 흐름에 오케스트레이션 사가 적용 — 계약 생성 → 초기
      납입금 출금 → 계약 확정 세 단계, 각 단계마다 보상 트랜잭션 정의
- [x] 출금 완료 후 계약 확정이 실패하는 경우 보상 거래(출금 롤백)가
      원장에 기록되는지 확인(완료 기준 나머지 절반) —
      `ProductSubscriptionSagaIntegrationTest`로 검증. 실제 클러스터
      배포(Docker·Helm·ArgoCD·CI)는 별도 작업으로 이어감
