## 문서 갭 — 구현 전 결정 필요

- [ ] **API-020 감사 로그 조회의 `ROLE_OPERATOR` 권한 모델 부재**: API설계 8절은
      운영자 전용(`ROLE_OPERATOR`)으로 명시하지만 운영자 역할 모델은 아직 없음(W3 API-004와
      동일 사유). W3과 같은 방식으로 인증된 사용자면 호출 가능하게 열어두고 ponytail 주석
      처리, 운영자 로그인이 생기면 `hasRole('OPERATOR')`로 좁힌다.

## 백엔드 (`apps/jbank-api`)

### 감사 로그

- [x] `AuditLog` 엔티티 + Flyway 마이그레이션 (ERD 2.8절 — `target_type`/`target_id`로
      임의 엔티티를 참조하는 범용 로그, 강한 외래키 없음)
- [x] `common.event`에 도메인 이벤트 정의 (계좌 상태 변경, 이체 완료, 고객 등급 변경) —
      폴더구조 4.2절 의존 방향 규칙에 따라 `support`는 이 이벤트만 구독하고 도메인을
      직접 호출하지 않음
- [x] `support` 패키지에 감사 로그 리스너 구현 — 감사 기록 실패가 본 거래를 실패시키면
      안 되는 이벤트와 반드시 함께 커밋돼야 하는 이벤트를 구분해 리스너 트랜잭션 전파
      속성을 각각 다르게 설정
- [x] 계좌 상태 변경·이체 완료·고객 등급 변경 세 지점에 이벤트 발행 연결
- [x] API-020 GET /admin/audit-logs 구현 (FR-SUP-001)

### 위험도 이력

- [x] `CustomerRiskAssessmentHistory`에 등급 변경 시점 스냅샷 기록 로직 (ERD 2.6절)

      예외 없이
