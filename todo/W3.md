## 백엔드 (`apps/jbank-api`)

### 공통 인증 기반

- [x] `customers` 테이블에 `login_id`, `password_hash` 컬럼 추가 마이그레이션, `Customer` 엔티티 반영
- [x] `CustomerRegisterRequest`에 `loginId`/`password` 추가, bcrypt 해시 후 저장
- [x] Spring Security 6 필터체인 구성 — `SecurityConfig`를 W1 임시 permitAll 버전에서 교체
- [x] JWT 액세스·갱신 토큰 발급 (`auth.jwt` 패키지) — 서명·만료 처리
- [x] 갱신 토큰 화이트리스트를 Redis에 저장, 재사용 탐지 시 해당 사용자 토큰 계열 전체 폐기
- [x] 인증·갱신·CSRF 세 쿠키 발급/삭제 처리 (`access_token`, `refresh_token`, `XSRF-TOKEN` — HttpOnly/Secure/SameSite=Lax, API설계 2.2절)
- [x] CSRF 이중제출 검증 필터 — GET·API-011·API-001(익명 등록이라 예외 추가) 제외, 나머지 상태변경 요청은 쿠키·헤더(`X-CSRF-TOKEN`) 일치 검증, 실패 시 `COMMON_007_CSRF_TOKEN_INVALID`
- [x] 로그인 연속 실패 Redis 카운터 — 5회 초과 시 30분 계정 잠금(`AUTH_002_ACCOUNT_LOCKED`, 423)
- [x] CORS 설정 — 로컬 프론트엔드 도메인만 허용, 자격증명 전송 허용
- [x] `ErrorCode`에 `AUTH_001_INVALID_CREDENTIALS`(401), `AUTH_002_ACCOUNT_LOCKED`(423), `AUTH_003_REFRESH_TOKEN_INVALID`(401) 추가

### 인증 API

- [x] API-011 POST /auth/login — bcrypt 검증, 세 쿠키 발급, 본문엔 만료시각·표시정보만
- [x] API-014 POST /auth/refresh — 갱신 쿠키로 재발급, 로테이션 + 화이트리스트 검증
- [x] API-015 POST /auth/logout — 화이트리스트 제거, 세 쿠키 모두 Max-Age=0으로 만료

### 기존 엔드포인트 소유자 확인 교체

- [x] API-002 계좌개설 — customerId를 요청 본문 대신 인증 주체에서 유도
- [x] API-003 계좌 상세조회 — customerId 쿼리 파라미터 제거, 세션 기반 소유자 확인
- [x] API-004 계좌 상태변경 — 운영자 역할 모델이 없어(구현계획 어디에도 W3 범위로 명시 안 됨) 인증된 사용자면 호출 가능하도록 남기고 ponytail 주석 처리 (운영자 로그인 생기면 `hasRole('OPERATOR')`로 좁힘)
- [x] API-005 계좌 해지 — customerId 쿼리 파라미터 제거, 세션 기반 소유자 확인
- [x] API-006~010(입금·출금·이체·잔액·거래내역) — 계좌 소유자 확인 신규 추가(기존엔 전혀 없었음)
- [x] API-017 고객별 계좌목록 — path의 customerId와 인증 주체 일치 확인

### 상품 도메인
