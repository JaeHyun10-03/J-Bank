# 2026-08-24 비용 통제 워크스페이스, 상품 화면 가입·조회, 인프라 파괴 후 재생성 검증

W6 남은 항목(인프라 2개, 프론트엔드 상품 화면) 마무리 세션. 인프라
파괴·재생성 검증을 실제로 돌리면서 방치돼 있던 버그 2건도 같이
잡았다.

## 1. 비용 통제용 워크스페이스 분리

`docs/06_J-Bank_인프라아키텍처.md` 12절 "상시 구동 구성과 시연
구성을 Terraform 워크스페이스로 분리"를 그대로 구현. `envs/dev/main.tf`에
`terraform.workspace == "demo"` 분기를 두고, demo 워크스페이스에서만
RDS Multi-AZ를 끄고 EKS 노드그룹을 1대로 줄인다. default(=always-on)는
기존 상시구동 사양 유지.

## 2. 상품 화면(가입·조회)

먼저 갭 확인: 백엔드 seed 상품은 `SAV-6M-001` 같은 무브랜드 정기적금
4종인데, 프론트(`app/products`)는 08/19 세션에서 만든 피그마 시안
그대로 J키즈 적금·J팜 농장 등 브랜드 상품명 하드코딩 + 미연동
상태였다(그날 devlog에 이 갭이 정확히 기록돼 있었다). 가입신청
(`subscribe`)·내 가입상품(`contracts`)은 아직 `ScreenPlaceholder`.

사용자 확인 후 "seed를 피그마 기준으로 교체" 방향으로 정리:

1. `SeedDataRunner`의 상품 4종을 `j-kids`/`j-farm` 2종으로 교체.
   테스트는 자체 mock fixture라 영향 없음 확인 후 진행.
2. 상품 목록 화면 하드코딩 배열 제거, `GET /api/v1/products`
   실연동. 백엔드에 없는 우대금리(topRate) 표시는 걷어냄. 대출·카드는
   여전히 도메인이 없어(기존 ponytail 주석) 정적 유지.
3. 가입신청·완료 화면 구현 — 출금계좌 선택 → 가입금액 입력
   (`AmountKeypad` 재사용) → `POST /products/{code}/subscriptions` →
   계약번호·만기일 안내. `domain-error-map.ts`에 PRD_001(최소금액
   미달)/PRD_002(판매중지) 추가. J팜 "농장 만들기" CTA를 이 화면에
   연결.
   - J키즈는 원래 CTA가 "J키즈 통장" 개설 온보딩으로 가는 별도
     흐름이라 이번 스코프에서 제외했다(건드리면 기존 온보딩 순서가
     깨짐).
4. 내 가입상품 조회 화면 구현 — `GET /customers/{id}/contracts` 목록.

## 3. 인프라 전체 파괴 후 재생성 검증

AWS 계정이 완전히 빈 상태(bootstrap도 미apply)라 bootstrap부터
시작: bootstrap apply → envs/dev demo 워크스페이스 첫 apply.

**1차 apply에서 발견한 버그 2건**(모두 기존 코드의 하드코딩 기본값이
시간이 지나 AWS 쪽 지원이 끊긴 경우):

- RDS PostgreSQL `16.4`가 더 이상 제공되지 않음
  (`InvalidParameterCombination`) → `16.15`로 갱신.
- EKS `1.30`이 표준지원 종료라 노드그룹 AMI를 못 만듦
  (`InvalidParameterException`) → `1.34`로 갱신. 클러스터
  마이너 버전은 한 단계씩만 in-place 업그레이드가 되는데 1.30→1.34는
  건너뛰므로, 기존 컨트롤플레인을 명시적으로 destroy한 뒤 재생성.

버전을 고치고 재apply해서 RDS·EKS·ElastiCache·ALB까지 전부
생성했는데, `kubectl`로 클러스터에 붙었더니 인증 실패
(`the server has asked for the client to provide credentials`).
원인은 `terraform-aws-modules/eks`의
`enable_cluster_creator_admin_permissions` 기본값이 `false`라
terraform을 실행한 IAM 사용자가 access entry에 자동 등록이 안
된 것 — `true`로 켜서 고침.

이 상태로 **전체 파괴(88개 리소스) → 재생성(88개 리소스)**을 한
사이클 돌려서 RDS available·EKS ACTIVE·ElastiCache available·ALB
active·`kubectl get nodes` 성공까지 확인. 검증 끝나고 과금 방지를
위해 다시 전체 destroy.
