## `OutboxEvent` 엔티티 + 마이그레이션(V9)

ERD 2.9절 그대로: `aggregate_type`/`aggregate_id`/`event_type`/`payload`(JSONB)/
`status`/`retry_count`/`last_error`/`occurred_at`/`published_at`. `AuditLog`와
같은 스타일로 생성자는 `PENDING`·`retry_count=0` 상태로만 만들고, 상태 전이용
메서드는 아직 안 붙였다 — 이체 트랜잭션 내 저장과 폴링 발행기 연동은 금요일
몫이라 그때 실제로 쓰는 시점에 같이 추가한다.

폴링 발행기가 미발행 레코드만 반복 조회하므로 `status='PENDING'`인 행만 담는
부분 인덱스(`idx_outbox_pending`)를 마이그레이션에 같이 넣었다. ERD 문서가
설명하는 이유 그대로: 인덱스 크기가 전체 행이 아니라 미발행 행 수에만
비례해서, 발행 완료 레코드가 쌓여도 인덱스는 거의 비어 있는 상태로 유지된다.

## 거래내역 조회 10만 건 EXPLAIN 벤치마크 — 절차만 준비

이 세션 샌드박스에는 Docker/Postgres가 없어(`docker info` 실패) 실제로 데이터를
채우고 측정할 수 없었다. 대신 `perf/sql/seed-100k-transactions.sql`(트랜잭션
10만 건 생성 스크립트)과 `perf/README.md`에 실행 절차·EXPLAIN 쿼리를 남겨뒀다.
todo 체크박스는 실행 전이라 미완료로 남겨둔다. 로컬에서 절차대로 돌리고
응답시간·실행계획 결과를 `perf/README.md`에 채우면 이 항목이 끝난다.
