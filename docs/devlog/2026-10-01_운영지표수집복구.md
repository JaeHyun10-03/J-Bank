# 2026-10-01 운영 Prometheus api 지표 수집 복구

운영 Prometheus가 api 지표를 하나도 못 모으던 문제를, actuator를 Compose 내부 전용 관리 포트(9095)로 분리하고 그 포트의 `/actuator/prometheus`만
인증 없이 여는 방식으로 고쳤다. 명세: `.claude/tasks/prod-metrics-scrape/task.md`, 결정: [ADR 0013](../adr/0013-management-port-metrics.md).

## 한 일

- **원인 확인**: SSM 읽기 전용 조회에서 target `api:8080` health=down, lastError `server returned HTTP status 401`, `up`=0이었다.
  필터체인이 `/actuator/health/**`만 공개하고 나머지는 JWT 쿠키를 요구한다. 코드를 읽다가 가입이 공개라 로그인한 아무 고객이나 외부
  `api.j-bank.site/actuator/prometheus`를 200으로 읽을 수 있다는 것도 찾았다(perf `metrics_proxy.py`가 그 방식).
- **선택**: 8080 공개 + caddy 차단, Prometheus 전용 인증, metrics_proxy 재사용, 관리 포트 분리 중 관리 포트 분리를 골랐다. 앱 안에서
  "어느 포트로 들어왔는지"로 경계를 두면 caddy 설정 하나에 보안을 기대지 않는다.
- **api**: `PrometheusScrapeRequestMatcher`(관리 포트 + `GET /actuator/prometheus`만 허용), 본 포트 `/readyz`·`/livez` 공개,
  매핑 없는 경로 404 `COMMON_004`, 메모리 기본 사용자 자동 구성 제외(기동 로그의 생성 비밀번호 문구 제거).
- **프론트·인프라**: 서버 상태 확인을 `/readyz`로, 운영 compose에 `MANAGEMENT_SERVER_PORT=9095`(호스트 미매핑), healthcheck와
  Prometheus 대상을 9095로.

## 겪은 문제

- **같은 포트에도 `local.management.port`가 있다**: 계획과 계획 리뷰는 "관리 포트를 설정하지 않으면 `local.management.port`가
  없다"고 전제했다. 그 전제로 "값이 있고 요청 포트가 같으면 허용"만 짰더니, 관리 포트를 나누지 않은 통합 테스트에서 본 포트
  미인증 `/actuator/prometheus`가 200이 나왔다. Boot의 `SameManagementContextConfiguration`이 같은 포트일 때 `local.management.port`를
  `local.server.port` 별칭으로 채우기 때문이다. 그대로 나갔다면 운영에서 관리 포트 설정이 빠지는 순간 지표가 외부에 열렸다.
  "관리 포트 != 본 포트" 조건을 더하고 단위 테스트도 실제 Environment 상태(같은 포트는 별칭, -1은 값 없음)로 고쳤다.
- **테스트에서 prometheus가 404**: 처음엔 관리 포트 prometheus가 200 대신 404였다. Boot 테스트는 기본으로 지표 내보내기를 꺼서
  엔드포인트 자체가 없다. `@AutoConfigureObservability`로 운영과 맞췄다. 이 404 때문에 위의 같은 포트 문제도 처음엔 401 대신 404로
  가려져 있었다.
- **없는 경로가 500**: "본 포트에 actuator가 없다"를 404로 보이려 했는데, `GlobalExceptionHandler`의 `Exception` 처리기가
  `NoResourceFoundException`을 500으로 바꾸고 있었다(계획 리뷰 2회차 지적). 사용자 결정으로 없는 경로 전체를 404 `COMMON_004`로 바꿨다.
- **Host 헤더 위조 테스트**: `getServerPort()`는 Host 헤더 값이라 본 포트로 `Host: ...:9095`를 보내면 위조된다. 그래서 `getLocalPort()`로
  판별한다. 이걸 테스트하려니 JDK HttpClient는 Host 헤더를 못 바꾼다. 소켓으로 직접 보내고, 같은 Host로 관리 포트에 보낸 요청은 200인
  대조 사례를 함께 둬 테스트가 공허하게 통과하지 않게 했다. `getServerPort()`로 판별했다면 위조 요청이 허용돼 401이 아니라 404가 된다.
- **worktree와 hook**: 처음 세션은 worktree로 옮겨 일했지만 hook은 프로세스 시작 시 프로젝트 경로(메인 체크아웃)의 workflow.py를 불러,
  verifier 호출이 다른 작업 상태에 기록됐다. 계획 리뷰 1·2회차가 공식 기록이 되지 못했고, worktree를 프로젝트로 연 새 세션에서 3회차를 받았다.
