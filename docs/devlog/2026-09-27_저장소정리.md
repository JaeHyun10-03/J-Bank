저장소 전체를 훑어 불필요한 파일과 어색한 폴더 구조를 점검했다. Git이 추적하는 603개 파일은
대체로 깔끔했고, 정리할 것은 로컬 잔여물과 위치가 어색한 파일 몇 개였다. 하네스 작업 `repo-cleanup`로 진행했다.

## 커밋 구성 (`chore/repo-cleanup`)

1. `docs(frontend)` create-next-app 기본 README를 실행·테스트 명령 안내로 교체.
2. `chore(infra)` bootstrap OIDC 주석의 "EKS·RDS·ElastiCache를 만드는 모듈" 표현을 현재 구성(ec2 모듈의 SSM 인스턴스 역할)으로 수정.
3. `docs` `todo/` → `docs/roadmap/`. 주차별 체크리스트는 끝난 기록이라 루트에서 내렸다.
4. `build(api)` `infra/docker/jbank-api/Dockerfile` → `apps/jbank-api/Dockerfile`. 빌드 컨텍스트가 원래 `apps/jbank-api`라 COPY 경로는 그대로다. compose는 `dockerfile: Dockerfile`, backend-cd는 `-f` 경로만 바꾸고 paths 필터의 `infra/docker/**`는 `apps/jbank-api/**`가 덮으므로 뺐다.
5. `chore(perf)` `scripts/perf.sh` → `perf/run-transfer.sh`. 옆의 `run-10m.sh`와 이름 규칙을 맞췄다. `ROOT_DIR=$(dirname)/..` 계산은 위치가 바뀌어도 같다.
6. `chore(harness)` `tests/` → `.claude/tests/`. 루트 `tests/`가 앱 테스트처럼 보였다. `ROOT`를 `parents[2]`로, checks.json·harness-ci(paths와 명령)·문서를 갱신.
7. `docs` 쓰지 않던 `contracts/bruno` 컬렉션 표기 제거.

로컬 잔여물(Git 밖): 빈 `contracts/bruno/`, 옛 PR 본문 초안, `.DS_Store`를 지웠다.

## 발견한 것

### "미사용" SVG가 실제로는 쓰이고 있었다

`icon-chevron-up.svg`를 파일명 grep으로 찾지 못해 미사용으로 판정했는데, `j-kids.tsx`가
`` `icon-chevron-${open ? "up" : "down"}.svg` ``로 경로를 조립하고 있었다. 지웠다면 아코디언을 펼칠 때
아이콘이 404가 나고, lint·tsc·Jest·build는 모두 통과했을 것이다. verifier 계획 리뷰에서 잡혔다.
교훈: 정적 자산 삭제 전에는 파일명 전체가 아니라 경로 조각(`icon-chevron-`)으로도 검색한다.

### 참조 검색 명령은 이동 전에 양성 대조부터

옛 경로 잔존 검사용 `git grep` 패턴을 이동 전에 먼저 돌려 알려진 위치가 잡히는지 확인했다.
`"-s", "tests"`(checks.json의 JSON 배열 표기)가 `-s tests` 패턴에 안 잡히는 걸 이때 발견해 보강했다.
빈 출력이 "참조 없음"인지 "패턴이 틀림"인지는 대조 없이는 구분할 수 없다.

### testing-policy.md는 하네스 계획 지문 입력이다

성능 명령 경로(`scripts/perf.sh`) 한 줄을 고치자 계획 지문이 바뀌어 코드 수정 Hook이 막혔다.
계획 재검증과 `start`를 다시 해야 했다. 다음에 testing-policy를 건드리는 작업은 그 변경을 가장
먼저(또는 계획 확정 전에) 하도록 커밋 순서를 짠다.

### compose `--profile api` 단독 config는 원래 실패한다

api 서비스가 core 프로필의 postgres·redis에 의존해서다. 이번 변경과 무관한 기존 구조라
`--profile core --profile api`로 확인했다.
