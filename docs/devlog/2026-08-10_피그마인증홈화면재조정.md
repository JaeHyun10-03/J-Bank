# 2026-08-10 피그마 기준 인증·홈 화면 재조정

## 배경

어제(2026-08-09) 만든 로그인·회원가입·홈 화면이 피그마(`Bank`,
fileKey `rB8P0k4VRswqKrCjlE4c9s`)를 전혀 참고하지 않은 데스크톱
카드 폼이었다. 피그마는 393px 모바일 프레임에 인증 플로우를
Auth1~Auth11 10개 화면으로 쪼개놓았는데, 기존 코드는 로그인·회원가입
각각 필드를 한 화면에 몰아넣은 shadcn Card였다. `get_design_context`로
화면 10개(Auth1-Splash, Auth3-Onboard, Auth4-Name, Auth5-Ssn,
Auth6-Phone, Auth7-OtpCode, Auth8-DeviceDone, Auth9-PinSetup,
Auth11-Login, Home)를 다시 조회해 재조정했다.

## 백엔드 계약과 피그마 플로우의 간극

피그마 인증 플로우는 이름→주민번호→휴대폰→SMS인증→기기인증→PIN
등록으로 끝나는데, 실제 백엔드는 `loginId`+`password` 인증만
있고 SMS 발송/검증 API도 PIN 로그인도 없다(`AuthController`는
`/login`·`/refresh`·`/logout`뿐). 다음처럼 다리를 놓았다:

- **로그인ID = 휴대폰번호.** 피그마 로그인 화면(Auth11)이 "이 기기가
  사용자를 기억한다"는 전제로 PIN 넘패드만 보여주는 것과 같은 맥락
  — 실사용 뱅킹 앱에서 흔한 패턴이다.
- **비밀번호 = PIN 설정 화면(Auth9)에서 받은 6자리.**
  `CustomerRegisterRequest.password`는 `@NotBlank`뿐 길이 제약이
  없어 그대로 써도 된다.
- **생년월일**은 입력 화면이 없어 주민번호 앞 6자리(YYMMDD)+뒷자리
  첫 숫자(성별/세기 코드)로 역산한다(`lib/resident-reg-no.ts`).
- **본인인증방법**은 NON_FACE_TO_FACE 고정, 주소·직업·거래목적·
  자금원천은 optional이라 비워서 전송한다.
- **SMS 인증번호**는 발송/검증 API가 없어 값 입력만 받고 그대로
  통과시킨다(가짜 통과 — 사용자 승인 하에 진행).
- **Auth2-Permission**(카메라·FaceID 등 OS 네이티브 권한 안내)은
  웹에 대응 개념이 없어 스킵했다. 피그마 문서 자체가 Auth10-Bio를
  이미 같은 이유로 컷한 전례가 있다.

## 화면 구조

- `/welcome` — Auth1-Splash. 비로그인 기본 진입점을 `/login`에서
  이곳으로 바꿨다.
- `/signup/onboard` — Auth3-Onboard, 3단계 안내.
- `/signup/name` → `/ssn` → `/phone` → `/otp` → `/device-done` →
  `/pin` — Auth4~9. 상태는 새 zustand 스토어
  `signup-wizard-store`로 단계 간 공유하되, 주민번호가 담기므로
  localStorage에는 영속화하지 않는다(새로고침하면 처음부터).
  `/pin`에서 6자리를 다 누르면 실제 `POST /customers` →
  `POST /auth/login`을 호출한다.
- `/login` — Auth11-Login. PIN 넘패드. `localStorage`의
  `jbank_last_login_id`(가입·로그인 성공 시 저장)로 이 기기가 마지막에
  쓴 로그인ID를 기억한다. 저장된 값이 없으면(최초 접속 등)
  `/login/id`로 보낸다.
- `/login/id` — 기존 아이디/비밀번호 폼을 그대로 옮겼다. 피그마
  "다른 방법으로 로그인" 링크가 가리키는 대상이자, 피그마에
  대응 화면이 없는 유일한 인증 화면이라 스타일은 손대지 않았다.
- `/`(Home) — 피그마 AccountCard·TabBar 재사용. 다만 피그마 Home은
  토스 특유 위젯(외부은행 연동 카드, 카드사용내역 캐러셀, 설문
  피드백 카드)까지 있는데 이 앱엔 없는 기능이라 뺐다. 계좌도
  한 장 고정이 아니라 보유한 만큼 카드로 나열한다. 탭바는
  홈·상품만 실제 라우트, 나머지는 피그마 문서에 이미 기록된
  "의도적 보류"와 같은 이유로 비활성이다.

새로 만든 공유 컴포넌트: `components/mobile-screen.tsx`(393px 프레임
래퍼), `components/pin-keypad.tsx`(PIN 점 표시기 + 넘패드, 재배열
버튼은 실제로 숫자 배치를 셔플한다).

EDD·계좌상세·거래내역 화면은 피그마 디자인 자체가 없어 손대지 않았다.

## 브라우저로 확인한 버그 1개 — next build와 next dev 동시 실행 시 캐시 깨짐

커밋마다 `next build`로 확인하면서 진행했는데, 이미 떠 있던 dev
서버(같은 `.next` 디렉터리를 씀)와 build가 충돌해 CSS 청크 요청이
페이지 HTML을 그대로 반환하는 상태가 됐다 — 브라우저에 스타일이
전혀 안 먹은 날것 HTML로 렌더됐다. dev 서버를 죽이고 `.next`를
지운 뒤 build → dev 순서로 분리하고 나서야 해결됐다. 이후로는
dev 서버를 내려놓고 build를 돌리는 순서를 지켰다.

## 검증

Chrome 브라우저 자동화로 전체 플로우를 실제로 눌러 확인했다:
`/welcome` → 온보딩 → 이름/주민번호/휴대폰/인증번호/기기인증완료
→ PIN 6자리 입력 → 실제 `POST /customers`+`POST /auth/login` 성공
→ `/accounts/open` 리다이렉트. 이어서 `/login`에서 같은 PIN으로
재로그인 성공, `/login/id`로 시드 계정(kim01) 로그인 후 홈에서
계좌카드·잔액·이체하기 버튼 동작까지 확인했다. `npx next build`,
`npx jest`(5개 전부 통과) 각 커밋마다 확인.

## 남은 것

- `/login/id`, EDD, 계좌상세, 거래내역은 피그마 디자인이 없어 이번
  범위 밖.
- 피그마 SMS 인증은 여전히 가짜 통과다 — 실제 SMS 발송 연동은 이
  프로젝트 범위에 없다.
- 홈 탭바 혜택·서비스·전체는 화면 자체가 없어 계속 비활성이다.
