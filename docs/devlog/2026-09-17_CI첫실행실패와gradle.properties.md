# 2026-09-17 CI 첫 실행 실패와 gradle.properties

## 배경

상품 서비스 통합·메시징 제거 작업을 PR #2(`refactor/api-product-integration`)로
올렸는데 `backend-ci`의 `build`, `openapi-drift` 두 job이 모두 실패했다. PR #1도
같은 결과였다. 이 워크플로는 `pull_request` 트리거만 있고 그동안 main에 직접
푸시해 왔기 때문에, 이번이 실질적인 첫 실행이었다.

## 원인 좁히기

1. **PR 코드 문제인가?** 로컬에서 `./gradlew clean compileJava compileTestJava`
   성공. `com.jbank.*` import 전부가 git에 추적된 파일과 대소문자까지 일치하는지도
   확인(macOS는 대소문자를 구분하지 않아 Linux 러너에서만 터지는 경우 대비).
   문제 없음.
2. **merge 결과 문제인가?** `pull_request`는 base와 합친 커밋을 빌드한다.
   `origin/main`은 PR #1 merge 커밋뿐이라 내용 차이 없음.
3. **step 소요 시간** — `Compile` step이 **5초**에 실패. Gradle이 컴파일을 시작도
   못 한 시간이다. `openapi-drift`도 `./gradlew bootRun`이 뜨지 않아 대기
   타임아웃. 두 job의 공통점은 "Gradle 기동".
4. 로그는 저장소 admin만 볼 수 있어(`Must have admin rights to Repository.`)
   Gradle 관련 추적 파일을 훑었다. `apps/jbank-api/gradle.properties`:

   ```
   org.gradle.java.home=/opt/homebrew/opt/openjdk@21
   ```

   최초 스캐폴딩 커밋(19f669e)부터 들어 있던 macOS Homebrew 경로. ubuntu 러너에는
   없는 경로다.

## 재현

```bash
./gradlew help -Dorg.gradle.java.home=/opt/nonexistent
```

```
* What went wrong:
Value '/opt/nonexistent' given for org.gradle.java.home Gradle property is invalid (Java home supplied is invalid)
```

Gradle은 이 프로퍼티가 가리키는 경로가 없으면 데몬을 띄우기 전에 종료한다.
5초 실패와 일치.

## 해결

`fix(ci): gradle.properties의 로컬 JDK 경로 제거` — 파일 자체를 삭제.

- CI: `actions/setup-java`가 `JAVA_HOME`을 잡아주고 `gradlew`는 그걸 쓴다.
- 로컬: 같은 줄을 `~/.gradle/gradle.properties`로 옮겼다. 개인 환경 의존 설정은
  저장소 밖에 두는 게 원칙.

## 배운 점

- "CI가 왜 실패하나"에서 **step 소요 시간**이 가장 빠른 힌트였다. 5초짜리 컴파일
  실패는 컴파일 에러가 아니다.
- 저장소에 들어간 `gradle.properties`는 팀 공통 값(버전, JVM 옵션)만 담아야 한다.
  절대 경로가 보이면 그 파일은 잘못된 위치에 있다.
- `pull_request` 트리거만 있는 워크플로는 첫 PR까지 한 번도 안 돈다. 스캐폴딩
  직후 빈 PR로라도 한 번 돌려보는 게 싸다.

## 남은 것

- `actions/setup-java@v4` deprecated 경고. 차단 요인은 아니라 별도 `ci` 커밋으로
  v5 전환 예정.
