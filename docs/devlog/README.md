# 개발일지

면접 준비용. ADR(`docs/adr/`)은 "무엇을 왜 그렇게 결정했는지"만 남기고, 여기는 "그 결정에 이르기까지 뭘 겪었는지"를 남긴다. 겪은 문제, 원인을 어떻게 좁혔는지, 무엇으로 해결했는지, 그 과정에서 뭘 배웠는지를 시간 순으로 적는다.

파일명은 `W{n}.md`(주차 단위, `todo/W{n}.md`와 동일 기준). 그 주에 작업할 때마다 새 파일을 만들지 않고 해당 주 파일에 `## YYYY-MM-DD 주제` 절을 이어 붙인다. 커밋을 마칠 때마다 그 커밋에 대한 절을 추가하는 것을 기본으로 한다.

## 쓰는 기준

- 결과만 적지 않는다. 처음에 뭘 시도했다가 왜 실패했는지도 남긴다. 면접에서 "왜 그렇게 했나"는 항상 실패한 경로까지 물어본다.
- 재현 가능한 수준으로 적는다. 에러 메시지 원문, 명령어, 버전을 그대로 남긴다.
- 이 문제를 몰랐다면 뭐가 더 힘들었을지, 다음에 비슷한 문제를 만나면 뭘 먼저 볼지 한 줄로 정리한다.
