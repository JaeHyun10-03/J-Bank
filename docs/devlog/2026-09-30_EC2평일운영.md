# 2026-09-29~30 운영 EC2 평일 09~18시 운영

비용 때문에 운영 EC2를 손으로 꺼 두자 main 머지마다 backend-cd가 `InvalidInstanceId`로 실패했고, 새벽 cron 배치는 한 번도 돌지 않았다.
끄는 것 자체를 자동화하고 꺼진 시간의 부작용까지 정리했다. 결정: `docs/adr/0011-ec2-weekday-hours.md`, 명세: `.claude/tasks/ec2-weekday-schedule/`.

## 한 일

- EventBridge Scheduler로 평일 09시 시작, 매일 18시 중지. 스케줄러 역할은 이 인스턴스 Start/Stop만
- backend-cd: 인스턴스가 꺼져 있으면 이미지만 올리고 배포 스킵(경고), 켜져 있으면 SSM 준비를 기다려 배포. 이미지에 revision 라벨
- 부팅 작업(systemd): 최신 이미지 반영, 끊긴 배치 기록 정리, 배치 4종 실행. CTR·FDS는 마지막 완료일 다음 날부터 어제까지 따라잡기. 새벽 cron 제거
- CD와 부팅 작업은 같은 flock 잠금으로 순차 배포. 잠금은 호출하는 쪽이 잡음(중첩 교착 방지)
- 프론트: 백엔드 연결 실패만 `SERVER_OFFLINE`으로 구분하고 운영 시간 안내

## 부딪힌 것

- 계획 리뷰를 4번 받았다. 동시 배포 경합, 실행 중 스크립트 덮어쓰기, 끊긴 배치 기록 때문에 같은 날짜 재실행이 막히는 문제, 프록시 시간 제한이 처리된 이체를 "꺼짐"으로 오판할 위험을 구현 전에 잡았다
- 스케줄러 역할을 만든 직후 1회용 스케줄 생성이 "역할을 assume할 수 없음"으로 거부됐다. IAM 반영 지연이었고 잠시 뒤 성공
- 예전 cron 배치는 한 번도 실행된 적이 없었다. 인스턴스를 9/17 생성 당일 저녁에 꺼 둔 탓

## 검증

- 모의: 부팅 작업 27개 사례(amazonlinux:2023 컨테이너, 동시 배포 경합 포함), 배포 스크립트 15개 사례, 프론트 jest 29개
- 실제: 1회용 스케줄로 중지·시작, 머지 CD 설치, 같은 날 재부팅 2회, 실제 DB에서 끊긴 기록 정리 뒤 재실행, 18시 중지·09시 시작, 부팅 때 이미지 교체 2회, 꺼진 상태 CD 스킵
- 결과 리뷰 2회(1회차 비밀값 검사 기록 누락 지적 → 실행·기록)
