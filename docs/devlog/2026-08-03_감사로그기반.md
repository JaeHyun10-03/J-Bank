# 2026-08-03 감사 로그 기반 (W4 월)

목표: `todo/W4.md` 요일별 계획의 월요일분. `AuditLog` 엔티티/마이그레이션,
`common.event` 도메인 이벤트 정의, 감사 로그 리스너(트랜잭션 전파 속성 구분) 3개 커밋.

## 1. `AuditLog` 엔티티 + Flyway 마이그레이션 (V8)

ERD 2.8절 그대로 `audit_log` 테이블을 만들었다. `target_type`/`target_id`로 임의
엔티티를 참조하는 범용 로그라 강한 외래키를 걸지 않는다(ERD 문서 156줄에 근거가 이미
적혀 있음). 인덱스는 ERD 3절 표대로 `(occurred_at)`, `(target_type, target_id)` 두 개.

`detail` JSONB 컬럼은 별도 라이브러리(hypersistence-utils 등) 없이 Hibernate 6 네이티브
`@JdbcTypeCode(SqlTypes.JSON)`로 매핑했다. Spring Boot 3.5.16이 이미 Hibernate 6.6대를
쓰고 있어서 추가 의존성이 필요 없었다.

## 2. `common.event` 도메인 이벤트 정의

계좌 상태 변경(`AccountStatusChangedEvent`), 이체 완료(`TransferCompletedEvent`), 고객
등급 변경(`CustomerGradeChangedEvent`) 3종을 record로 정의했다.

처음엔 `AccountStatusChangedEvent`에 `AccountStatus` 도메인 enum을 그대로 썼는데,
그러면 `common`이 `account` 패키지를 의존하게 된다. 폴더구조 4.1절은 "모든 도메인
패키지는 `common`을 의존할 수 있다"는 방향만 규정하는데, 반대 방향(`common`이 도메인을
아는 것)까지 열어주면 `common`이 더 이상 진짜 리프 패키지가 아니게 되고, 이벤트를
새로 추가할 때마다 `common`에 도메인 의존이 하나씩 쌓이는 구조가 된다. 그래서 상태값과
등급값은 전부 `name()`으로 직렬화한 문자열로 바꿨다. 현재 `DependencyDirectionTest`는
이 반대 방향을 아직 검사하지 않지만, 검사가 없다고 위반해도 되는 건 아니라고 판단했다.

## 3. 감사 로그 리스너 (트랜잭션 전파 속성 구분)

`AuditLogListener`에 이벤트 3종을 구독하는 `@EventListener` 메서드를 각각 뒀다.

- `TRANSFER_COMPLETED`: 자금 이동 감사는 FR-SUP-001의 핵심 증적이라 감사 기록이
  실패하면 이체 자체도 실패해야 한다고 판단했다. 그래서 일반 `@EventListener`로 호출자
  트랜잭션에 그대로 참여시켰다(`REQUIRED`) — 감사 저장이 예외를 던지면 이체 트랜잭션
  전체가 롤백된다.
- `ACCOUNT_STATUS_CHANGED`, `CUSTOMER_GRADE_CHANGED`: 감사 실패가 본 업무를 막으면 안
  되는 이벤트로 분류했다. `@Transactional(propagation = REQUIRES_NEW)`로 별도
  트랜잭션에서 실행하고, 예외를 잡아 로그만 남기고 삼킨다.

이 분류(어느 이벤트가 REQUIRED고 어느 게 REQUIRES_NEW인지)는 W4.md 문서에 명시돼 있지
않은 설계 판단이라 커밋 전에 사용자에게 확인받고 진행했다.

## 남은 것

이벤트 발행 지점(계좌 상태변경·이체완료·고객등급변경 서비스 코드)에 실제로 연결하는
작업은 화요일분. 오늘 만든 이벤트/리스너는 아직 어디서도 발행되지 않는 상태다.

Docker 데몬이 로컬에 안 떠 있어 testcontainers 기반 통합 테스트(마이그레이션이 실제
Postgres에 적용되는지)는 이번엔 못 돌렸다 — `compileJava`와 ArchUnit
`DependencyDirectionTest`까지만 확인했다.
