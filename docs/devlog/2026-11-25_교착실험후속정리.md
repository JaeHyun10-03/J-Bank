# 2026-11-25 교착 실험 후속 정리

작업: `.claude/tasks/deadlock-docs-cleanup`. 교착 실험(`2026-11-25_교착재현실험.md`)에서 남긴 후속 중 문서와 실행 스크립트를 정리했다.

## 바꾼 것

- 실행 스크립트 `perf/run-deadlock.sh`의 `prod-all`이 서버를 건드리기 전에 두 실험 계좌의 사용 가능 잔액을 확인한다. 새로 시작하면 계좌마다 1억 원 이상, `--from` 재개는 합 2억 원 이상이어야 한다. 부족하거나 읽지 못하면 멈춘다.
- 실험 runbook을 24시 중지(ADR 0015) 기준으로 고치고 계좌 준비와 멈췄을 때 할 일을 적었다.
- 설계 문서 05·06·07의 CORS 설명을 정정했다.
- 결과 보고서, CORS 확인 기록, 메일 기록, 교착 개발일지의 문구를 사실에 맞췄다.

## 막힌 것

- **금액은 문자열이다**: API가 BigDecimal을 문자열로 준다. 첫 계획에는 금액이 문자열이라는 사실이 빠져 있었다. `.availableBalance >= 100000000`처럼 그대로 비교했다면 jq가 문자열을 숫자보다 크게 보아 `"0.00"`도 통과했을 것이다. 계획 검증에서 지적받아, 구현 전에 문자열을 해석해 전 단위 정수로 비교하는 조건을 정했다. 값이 없거나 숫자가 아니면 시작하지 않는다.
- **같은 값 조합으로는 잘못된 구현도 통과했을 것이다**: 계획의 처음 시나리오(실행 전)는 "각 1억"과 "합 2억"을 구분하지 못했다. 합은 2억 이상이지만 한 계좌가 부족한 조합을 넣었고, 일부러 틀리게 만든 스크립트 10종이 모두 실패하는지로 검사 자체를 확인했다.
- **검증을 잘못 호출했다**: 계획을 고치는 명령이 실패했는데 확인하지 않고 다음 검증을 불렀다. 수정 전 문서가 대상이라 바로 중단했지만 검증 한도를 한 번 썼다. 그 뒤로는 수정이 들어갔는지 먼저 확인하고 호출한다.
- **확인하지 않은 개설 방법을 적었다**: 교착 개발일지에 사용자가 주소로 계좌를 직접 열었다고 적었으나, 그렇게 말한 기록이 없었다. 방법을 안내했고 준비됐다고 들은 사실로 고쳤다.

## 남긴 것

- 잔액 확인은 운영에서 실제로 돌리지 않았다. 다음 운영 실험에서 처음 쓰인다.
