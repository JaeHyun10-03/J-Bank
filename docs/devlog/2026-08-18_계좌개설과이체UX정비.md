# 2026-08-18 로컬 실행 편의화, 계좌개설 화면 구현, 이체 UX 정비

계획된 `todo/W6.md` 작업이 아니라, 로컬에서 프론트를 직접 눌러보며
발견한 문제들을 그 자리에서 고친 세션이다.

## 로컬 풀스택 실행 스크립트

Docker(core+messaging+observability) + 백엔드 + 프론트엔드를 명령어
하나로 띄우는 `scripts/up.sh`를 추가했다. `scripts/dev.sh`의 "전부
올리는 단축 명령을 두지 않는다"는 원칙(폴더구조 문서 7절)은 k6
측정 조건을 프로파일 조합마다 고정해야 한다는 목적이라, 평소
개발용 실행과는 별개로 판단해 예외를 뒀다 — 성능 측정 시에는
여전히 `dev.sh core`로 좁혀 써야 한다. 기동 완료 후 프론트·백엔드·
스웨거 링크를 헬스체크 폴링 후 터미널에 출력하도록 추가 커밋으로
보강했다.

## 계좌개설 화면 구현

`app/accounts/open/page.tsx`가 `ScreenPlaceholder`만 렌더링하는
빈 스텁이었고, 홈 화면에서 계좌 없는 고객이 개설 화면으로 갈
경로도 없었다. API-002는 W1부터 있었으니 프론트만 없던 상태.
초기입금이 0원만 지원되고 상품유형도 `CHECKING` 고정이라 폼은
확인 버튼 하나로 충분했다. 홈 화면 빈 상태에 진입 버튼을 추가하고,
CDD 미완료·고객상태 이상 에러코드를 `domain-error-map.ts`에
반영했다.

## 이체 완료 후 입력화면으로 튕기는 버그

이체 확인/OTP 화면 둘 다 성공 시 `reset()`으로 스토어를 비우는데,
그 값(`toAccountNumber`/`transactionId`)의 부재를 감시하는
`useEffect`가 완료 카드 렌더링 뒤에 뒤늦게 걸려 입력화면으로
리다이렉트시키고 있었다. `result`가 세팅된 경우는 리다이렉트하지
않도록 조건을 추가했다. 즉시완료·OTP 경로 둘 다 같은 결함이었다.

이어서 완료 후 이동 위치도 계좌상세가 아니라 홈으로 바꿨다 —
이체는 여러 계좌를 넘나드는 행위라 완료 후에는 전체 계좌 현황이
자연스럽다.

## 계좌상세·거래내역 조회 디자인 통일

두 화면 다 shadcn Card/Table 기반 데스크톱 스캐폴드가 W1 이후
그대로 남아있어, `MobileScreen` 패턴으로 넘어간 나머지 화면들과
색·레이아웃이 어긋나 있었다. 같은 카드 스타일·타이포·간격 토큰으로
다시 짰다. 거래내역 필터·페이지네이션 기능은 그대로 두고 표현만
모바일 리스트로 바꿨다. 두 화면만 쓰던 `AppHeader`와 미사용으로
남은 shadcn `table`/`select` 컴포넌트는 삭제했다.

## 이체 입력을 단계형 위저드로 재구성

계좌번호·금액·메모가 한 화면에 다 보이던 플랫 폼을 토스/케이뱅크식
단계 진행(계좌번호 → 금액 → 메모)으로 바꿨다. 각 단계는 커스텀
숫자 키패드가 하단에 뜨는 방식으로 통일하고, 이전 단계 요약을
상단에 남겨 뭘 입력 중인지 보이게 했다. 계좌번호 자릿수 입력·
하이픈 포맷팅 헬퍼(`appendAccountDigit`/`formatAccountNumber`)를
`format.ts`에 추가했다. react-hook-form은 이 화면에서 뺐다 — 필드가
전부 커스텀 키패드로 채워지는 구조라 네이티브 입력 검증 라이브러리
보다 수동 상태관리가 더 짧았다.

## 검증

매 커밋마다 `eslint`·`tsc --noEmit` 통과 확인 후, Chrome
자동화로 실제 화면을 눌러 검증했다: 계좌 2개 개설 → 입금 → 이체
→(1차 재현으로 버그 확인)→ 수정 → 재이체로 완료 카드·잔액 반영·
홈 이동까지 재확인. 거래내역 조회 필터·페이지네이션도 실제 데이터로
확인.
