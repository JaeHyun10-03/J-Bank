# 2026-08-09 프론트엔드 인증·계좌 화면 6개 + 접근 제어 미들웨어 (W4 일)

목표: `todo/W4.md` 프론트엔드 트랙 마지막 항목. 로그인, 회원가입, EDD,
홈 계좌목록, 계좌상세, 거래내역 조회 화면과 접근 제어 미들웨어를
구현계획 8절 범위 그대로 만든다. 계좌개설 화면은 이번 주 범위가
아니라(문서에 명시적으로 빠져 있음) 손대지 않았다.

## 착수 전 발견한 갭 — 가입 직후 자동 로그인

`SecurityConfig`의 `PUBLIC_PATHS`는 `/api/v1/customers`(가입) 정확히
일치만 공개고, `/api/v1/customers/{id}/edd`와 `POST /api/v1/accounts`는
인증이 필요하다(`CustomerControllerTest`가 `AuthPostProcessors.asCustomer`로
호출하는 것으로 확인). 그런데 화면플로우차트 4절은 가입 → EDD/계좌개설
사이에 로그인 화면을 두지 않는다. 가입 성공 직후 방금 입력한 자격증명으로
로그인 API를 한 번 더 호출해 인증 쿠키를 받는 방식으로 메웠다 — 새
백엔드 엔드포인트 없이 기존 로그인 API 재사용.

## 화면 6개

각 화면은 `react-hook-form` + `zod`로 필수값만 검증하고(백엔드도
`@NotBlank` 이상은 안 함), 도메인 에러코드(`AUTH_001`/`AUTH_002`,
`ACC_001`/`ACC_003`)만 화면별로 분기해 처리한다. 공통 에러 응답에서
`code`/`message`를 꺼내는 `lib/api-error.ts` 하나로 통일했다.

- **로그인**: AUTH_001은 폼 에러, AUTH_002(계정 잠김)는 별도 화면.
  서버가 `LoginAttemptService`로 이미 잠금을 관리해서 클라이언트가
  실패 횟수를 셀 필요는 없다.
- **회원가입**: CDD 등록 → 자동 로그인 → `eddRequired`로 EDD/계좌개설
  분기. 생년월일은 `<input type="date">` 그대로 써서 별도 날짜
  라이브러리가 필요 없다.
- **EDD**: 회원가입에서 자동 로그인 시 저장해둔 `customerId`(zustand,
  `lib/auth-store.ts`)로 경로를 구성한다. 이 값 하나 때문에 W4 범위엔
  없는 "내 정보 조회" API가 아쉬운데, 로그인 응답에 이미 있는 값을
  들고 있는 것으로 충분했다.
- **홈/계좌상세/거래내역**: `@tanstack/react-query`로 조회한다. 축차
  프록시(`/api/proxy`)를 거쳐 기존 401 인터셉터(조용한 재발급)를
  그대로 재사용— 화면마다 인증 처리를 따로 안 짜도 된다. 계좌상세는
  `AccountDetailResponse`에 잔액 필드가 없어 잔액 조회 API를 별도로
  한 번 더 부른다. 거래내역은 date input을 백엔드가 요구하는 ISO
  OffsetDateTime으로 변환하는데, 종료일은 23:59:59.999까지 포함하도록
  보정한다(안 그러면 종료일 당일 거래가 빠짐).

입금/출금/이체/해지 버튼은 계좌상세에 달지 않았다 — W5 범위고, 아직
화면이 없는 곳으로 연결하면 오히려 헷갈린다.

## 접근 제어 미들웨어

`access_token`/`refresh_token` 쿠키 존재 여부만 본다. `access_token`은
JWT TTL과 같은 maxAge로 발급되므로 만료되면 브라우저가 쿠키 자체를
지운다 — "만료"를 별도로 판단할 필요 없이 "없음"과 같은 신호가 된다.
`access_token`만 없고 `refresh_token`은 남아 있으면 통과시켜 이미 있는
401 인터셉터가 처리하게 둔다. `/login`, `/signup`, `/api/proxy/**`만
공개 — `/api/proxy`를 막으면 로그인·가입 요청 자체가 막힌다.

## 브라우저로 직접 확인하다 발견한 버그 4개

코드는 빌드 통과 + 타입체크만으로는 못 잡는 문제들이었다. 시드
데이터(`--spring.profiles.active=local,seed`)로 백엔드를 띄우고 Chrome
브라우저 자동화로 로그인부터 거래내역까지 실제로 눌러보다 하나씩
나왔다.

1. **Input이 forwardRef가 아니었다.** shadcn이 생성한
   `components/ui/input.tsx`가 일반 함수 컴포넌트라 react-hook-form의
   `register()`가 넘기는 ref가 그냥 버려졌다. 콘솔 경고만 뜨는 게
   아니라 실제로 입력값이 항상 빈 문자열로 제출돼 로그인 폼에 값을
   써도 "Required" 에러가 계속 떴다. `React.forwardRef`로 감쌌다.
2. **Tailwind v4 기본 테마가 아예 안 실려 있었다.** `globals.css`가
   v3 방식 `@tailwind base/components/utilities`를 쓰고 있어서
   `--spacing`, `--text-*`, `--max-width-*` 같은 기본 테마 변수가
   하나도 로드되지 않았다 — `p-8`, `gap-4`, `h-8`, `max-w-sm` 같은
   숫자 스케일 유틸리티가 전부 무효했고, 이 프로젝트 `@theme`에 직접
   정의된 색상·radius나 `flex`/`items-center` 같은 키워드 유틸리티만
   살아있었다. 로그인 카드가 중앙정렬 안 되고 화면 전체 폭으로 퍼져
   있어서 발견했다. W3 스캐폴딩 때부터 있던 문제라 기존 페이지 전부에
   영향이 있었다. `@import "tailwindcss"`로 교체.
3. **금액 문자열이 truthy 판정을 깼다.** 백엔드가 BigDecimal을 정밀도
   보존 목적으로 JSON 문자열("0.00")로 내려서, `holdAmount ? ... :
   null` 같은 코드가 지급정지 금액이 0원인 계좌에도 안내 문구를
   띄웠다. `Number(value) > 0`으로 판단하는 `isPositiveAmount`
   헬퍼로 통일.
4. **로그인 401에 재발급 인터셉터가 걸렸다.** 응답 인터셉터가
   "`/auth/refresh` 호출 자체가 아니면 401은 재발급 대상"으로
   처리하고 있어서, 로그인 자체가 틀린 비밀번호로 401을 받아도
   조용한 재발급을 시도했다. 재발급도 쿠키가 없어 403으로 실패하면
   `window.location.href="/login"`으로 전체 페이지를 리로드해버려서
   입력값이 사라지고 AUTH_001 에러 메시지는 뜨지도 못했다. 로그인
   화면을 직접 눌러보다 발견했다 — 자동화 테스트만으로는 못 잡았을
   문제. `/auth/login`도 재발급 제외 목록에 추가.

이 중 2·4번은 이번에 만든 화면이 아니라 기존 스캐폴딩(W3)의 결함인데,
실제로 화면을 만들어 눌러보기 전까지는 드러나지 않았다.

## 검증

Chrome 브라우저 자동화로 다음 흐름을 실제로 클릭해서 확인했다:
미들웨어(비로그인 시 `/` → `/login` 리다이렉트) → 시드 계정(kim01)
로그인 → 홈(계좌 잔액 470,000원 정상 표시) → 계좌상세 → 거래내역
조회(전체/출금 필터 전환 확인) → 로그아웃(쿠키 만료 후 미들웨어가
다시 막는지 확인) → 회원가입(새 계정 park01, CDD → 자동 로그인 →
`eddRequired=false`라 계좌개설 화면으로 분기) → 로그인 실패(AUTH_001
인라인 에러) → 5회 연속 실패로 계정 잠김(AUTH_002 안내 화면).

EDD 분기(`eddRequired=true`)는 시드 계정이 전부 `LOW` 위험이라 UI로
직접 확인하지 못했다 — 코드 리뷰로만 확인. `npx jest`(5개 전부 통과),
`npx next build` 각 커밋마다 통과 확인.

## 남은 것

W4는 이걸로 완료. 남은 문서 갭은 `ROLE_OPERATOR` 권한 모델(결정 보류
중, ponytail 주석 처리돼 있음)뿐이고, 이건 운영자 로그인 자체가 생기는
주차에 다시 본다. W5부터는 입금/출금/이체/2차 인증 화면과 도메인
에러코드→폼 필드 매핑 테이블 작업.
