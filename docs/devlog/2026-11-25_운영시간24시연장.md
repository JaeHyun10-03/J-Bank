# 2026-11-25 운영 시간을 평일 24시까지 늘리기

작업: `.claude/tasks/ops-hours-midnight`. 결정은 ADR 0015.

## 계기

운영 EC2는 비용 때문에 평일 09~18시에만 켰다(ADR 0011). 18시가 지나면 배포 확인과 운영 실험을 다음 날로 미뤄야 해서 개발이 늦어졌다. 요일은 평일 그대로 두고 중지만 24시로 늦췄다.

## 바꾼 것

- 중지 스케줄 `cron(0 18 * * ? *)` → `cron(0 0 * * ? *)`. 시작 스케줄은 그대로다.
- 꺼짐 안내 문구를 "평일 09:00~24:00(KST)"로 바꾸고, 문구 값을 검사하는 테스트를 넣었다. 기존 테스트는 상수끼리 비교해서 문구가 틀려도 통과했다.
- 주석, runbook, 인프라 문서, README, 다이어그램 2개. ADR 0011·0014는 본문을 두고 상태에 안내 한 줄만 넣었다.
- 비용은 월 약 $11에서 약 $14가 된다.

배치 따라잡기는 KST 날짜로, 배포 건너뛰기와 화면 안내는 실제 상태로 판단해서 로직은 바꿀 것이 없었다.

## 계획에서 걸린 것

한 줄짜리 변경인데 계획 리뷰를 세 번 받았다.

- **주석만 고쳐도 배포가 돈다**: backend-cd 경로 필터에 `infra/compose/**`와 배포 스크립트가 들어 있다. 병합하면 api가 수십 초 재시작되므로 교착 실험이 없을 때 병합하기로 했다.
- **다른 작업이 같은 스케줄을 만진다**: 교착 실험은 그날만 연장하려고 중지 스케줄을 껐다가 저장본으로 되돌린다. 그 사이 apply하면 스케줄이 다시 켜지고, apply 전 저장본으로 되돌리면 18시로 돌아간다. apply 직전에 상태를 다시 보기로 했다.
- **에이전트는 대화형 apply를 못 한다**: "plan을 다시 확인하고 yes"라고 적었는데 입력할 터미널이 없다. 승인 뒤 plan 파일을 새로 만들어 대조하고 그 파일로 apply하는 절차로 바꿨다.

## 구현하며 막힌 것

- 하네스 start가 거부됐다. plan-review.md에 `최종 판정` 줄이 회차마다 있어서다. 지난 회차 줄에 회차 이름을 붙였다.
- 그때 verifier 응답을 줄여 적어 놓고 "원문"이라고 표기한 것을 발견했다. 규칙은 실제 응답 보존이라 원문으로 교체했다.
- `/usr/local/bin/docker`가 삭제된 OrbStack을 가리키는 깨진 링크라 Docker CLI를 쓸 수 없었다. Docker Desktop을 켜고 verify 명령의 PATH에만 실행 파일 경로를 넣었다.

## 결과

- verify 통과. plan은 중지 스케줄의 표현식 1건만 바뀐다(0 add, 1 change, 0 destroy).
- 2026-11-25 13:46 병합, 13:51 apply(0 added, 1 changed, 0 destroyed). 병합 재배포로 api가 다시 만들어지는 동안 `/readyz`가 502였다가 200으로 돌아왔다.
- 같은 날 18:23에 켜져 있었고 18시 전후 중지 기록이 없었다. 11-23과 11-24에는 18:00:22에 스케줄러 중지가 1건씩 있어, 같은 조회로 비교했다.
- 2026-11-26 00:00:22에 스케줄러가 인스턴스를 중지했다(CloudTrail 1건).
