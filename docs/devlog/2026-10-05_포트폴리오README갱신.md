# 2026-10-05 포트폴리오 README 갱신

## 배경

입금 비동기 반영(ADR 0012)이 끝나 이력서·포트폴리오에 쓸 이야기가 바뀌었다. README "주요 문제 해결"은
이미 제목 한 줄 → 그림 → 문제 원인 → 해결 과정 → 결과 양식이었는데, 핫 계좌 개선은 3번(부하 측정) 결과 끝에
한 줄로만 붙어 있었고 AI 활용 항목은 없었다. 문서만 바꾸는 작업이라 하네스 작업은 만들지 않았다.

## 커밋 구성 (`docs/readme-portfolio`)

1. `docs(readme)` 핫 계좌 입금 비동기 반영을 1번 항목으로 추가하고 그림 `hot-account-credit.svg`를 새로 그렸다.
   기존 1~4번은 2~5번으로 밀고, 부하 측정 항목에서는 async 결과 줄을 빼고 "병목 확인(1번에서 해결)"으로 바꿨다.
2. `docs(readme)` AI 하네스 검증 사례를 6번 항목으로 추가하고 그림 `harness-gate.svg`를 새로 그렸다.
3. `docs(devlog)` 이 문서.

## 수치를 고를 때 기준

- 핫 계좌 결과는 같은 부하 단계 비교(초당 100건 이체 p95 395 → 33ms, 무관한 조회 307 → 15ms)를 앞에 뒀다.
  무너짐 판정값(중앙값 95 → 115)은 CPU steal 일시 정지로 흔들려서 근거로 약하다.
- 최대 처리 TPS 205는 r5 한 회차 값이라 쓰지 않았다. 중앙값은 103.8 → 115.1이다.
- 무너질 때 무관한 조회로 번지는 것은 6/6으로 그대로라 "전파 해결"이라고 쓰지 않았다. 바뀐 것은 무너지는 지점 이전의
  지연과 그 뒤 회복(0/6 → 3/6)이다.
- 반영 지연은 측정 뒤 판정 범위를 초당 150건 이하로 좁힌 값(p95 220~404ms)이라 트레이드오프로 적고 결과 문서를 링크했다.

## AI 활용 수치 집계

6개 작업(ec2-load-test, ec2-load-test-followup, hot-account-baseline, async-credit, ec2-weekday-schedule, repo-cleanup)의
`plan-review.md`·`review.md`에서 verifier가 차단·중요로 표시한 지적을 세었다. 같은 지적의 해결 확인 줄은 빼고 지적 제목만 셌다.

| 작업 | 계획 리뷰 (차단 / 중요) | 결과 리뷰 (차단 / 중요) |
|---|---|---|
| ec2-load-test | 2 / 19 | 0 / 4 |
| async-credit | 1 / 10 | 1 / 6 |
| ec2-weekday-schedule | 0 / 11 | 0 / 1 |
| hot-account-baseline | 0 / 6 | 0 / 2 |
| repo-cleanup | 1 / 2 | 0 / 2 |
| ec2-load-test-followup | 0 / 2 | 0 / 0 |
| 합계 | 4 / 50 | 1 / 15 |

- 리뷰 기록 형식이 작업마다 달랐다(`### [중요]`, `**중요-1.`, `- [중요]`, 표 안의 `중요 1`). 처음 grep 한 가지 패턴으로
  셌을 때 ec2-load-test가 0건으로 나왔고, 해결 확인 줄(`**중요-1 근거**`)까지 세면 두 배가 됐다. 형식별로 원문을 보고 다시 셌다.
- 가장 의미 있는 사례는 async-credit 계획 리뷰의 [차단] F1이다. 해지가 락 없이 계좌를 읽고 전체 컬럼을 UPDATE해서,
  입금 반영과 겹치면 잔액 캐시가 사라지거나 해지 계좌에 입금이 영원히 남는 경로였다. 이 지적이 `FOR KEY SHARE`(이체)·
  `FOR UPDATE`(해지) 락 모드 설계로 이어졌다.
- 한계: verifier도 같은 계열 모델이라 완전히 독립된 검증은 아니다. README에도 그대로 적었다.
