# 2026-08-19 숫자 키패드 탭 피드백 추가

이체 화면 QA 중 "숫자 키패드 누를 때 인터랙션이 있으면 좋겠다"는
요청. brainstorming 스킬로 bounded 분류 후 짧게 설계·승인 받고
진행.

## 1차: CSS `:active`

`AmountKeypad`(`components/amount-keypad.tsx`)와
`PinKeypad`(`components/pin-keypad.tsx`) 버튼에
`active:bg-[#f2f4f6]` + `transition-colors`만 추가. 네이티브 CSS라
의존성도 상태도 필요 없다고 판단해 가장 가벼운 방식으로 먼저
커밋(`style(frontend)`).

## 문제 재현과 원인

사용자가 실제로 눌러보니 "짧게 클릭하면 안 보이고 길게 누르면
보인다"고 보고. 원인은 `mousedown → mouseup`이 한 프레임 안에
끝나는 빠른 탭에서는 브라우저가 `:active` 상태를 페인트할 기회
자체가 없다는 것 — CSS 의사클래스만으로는 지속시간을 보장할 수
없다.

## 2차: 최소 노출시간 보장

`lib/use-press-feedback.ts`에 작은 훅 추가:

- `onPressStart`: `pointerdown` 시 즉시 눌림 표시 + 타임스탬프 기록
- `onPressEnd`: `pointerup`/`pointerleave`/`pointercancel` 시 경과
  시간을 계산해 최소 100ms는 채우고 나서 해제

두 키패드 모두 CSS `:active`를 걷어내고 이 훅의 `pressed` state로
조건부 클래스(`cn`)를 적용하도록 교체. 동일 로직이 두 컴포넌트에
필요해서 훅 하나로 공유(중복 방지).

## 검증

Chrome으로 이체 금액 입력 화면에서 실제 클릭 후 스크린샷 확인 —
`pointerup` 이후에도 눌림 배경이 잔상으로 남아 있는 것을 캡처해
최소 노출시간이 실제로 적용됨을 확인. `npx tsc --noEmit`은 기존에도
있던 무관한 에러(`field.tsx`, 테스트 파일 jest 타입) 외에 신규
에러 없음.

## 커밋

1. `style(frontend)`: 숫자 키패드 탭 시 배경 피드백 추가 (CSS
   `:active`, 이후 대체됨)
2. `fix(frontend)`: 키패드 탭 피드백이 빠른 탭에서 안 보이는 문제
   수정 (`usePressFeedback` 훅으로 교체)

## 다음

- 100ms는 사용자 확인만 받은 값, 실측 튜닝은 안 함. 너무 길게/짧게
  느껴지면 `MIN_PRESS_MS` 하나만 조정하면 됨.
