# 2026-08-20 혜택·서비스·전체 화면 신설

하단 탭바의 남은 3개 탭(혜택/서비스/전체) 링크가 전부 `null`이던 걸,
피그마 `Bank` 파일 시안(node-id 61-46 / 63-56 / 133-2476) 그대로
채워 넣은 세션.

## 스코프 확인

세 화면 모두 상품/이체와 마찬가지로 백엔드에 대응 도메인·API가 없는
순수 마케팅 목업(리워드 카드, 인기혜택 리스트, 앱테크·자산관리
서비스 목록, 전체 메뉴 항목)이라 `ponytail:` 주석 + 고정 텍스트로
채웠다. 아이콘은 기존 관행대로 피그마 SVG 대신 `lucide-react`로
매핑(HelpCircle/Gift/Ticket/Percent/Globe, CreditCard/Sprout/Trophy,
Send/Smartphone/Calendar/ClipboardList/QrCode/Users/Wallet/Landmark/
CirclePlus/EyeOff 등). 리워드 카드 상단의 회전된 사각형 장식은
피그마에서도 이미지가 아니라 좌표 도형이라 그대로 `div` 두 개로
재현했다.

## 구현

1. `app/benefits/page.tsx` — 리워드 카드 3종(가로 스크롤) + 인기혜택
   리스트 5종. `app/products/page.tsx`의 카드 리스트 패턴 재사용.
2. `app/services/page.tsx` — 칩 3개 카테고리 전환(상태만 있고 실제
   필터링 대상은 "생활서비스" 목록뿐이라 다른 칩은 시각 상태만 동작)
   + 앱테크 5종 + 자산관리 2종 리스트. 상품 목록 화면과 동일하게
   `useState` 칩 전환 패턴 재사용.
3. `app/menu/page.tsx` — 검색바(비활성 표시만) + 이체/출금/계좌 3개
   섹션 카드, 섹션마다 컬러 아이콘 타일.
4. `BottomTabBar`의 혜택/서비스/전체 href를 각각
   `/benefits`·`/services`·`/menu`로 연결.

리스트 항목들의 chevron은 눌러도 이동할 목적지 화면이 없어서 전부
`Link`가 아닌 `div`로 정적 표시만 했다(이체결과 조회 같은 상세
화면이 실제로 생기면 그때 라우팅 연결).

## 검증

`tsc --noEmit`으로 신규/변경 파일에 타입 에러 없는 것 확인(기존
`field.tsx`/`api-client.test.ts` 에러는 이번 변경과 무관한 기존
이슈). 개발 서버(3000번 포트, 이미 기동 중)에 Chrome으로 접속해
`/benefits`·`/services`·`/menu` 세 화면 스크린샷을 피그마 시안과
대조, 하단 탭바 클릭으로 라우팅도 확인했다.

## 커밋

1. `feat(frontend)`: 혜택 탭 화면 신설, 하단 탭바 연결
2. `feat(frontend)`: 서비스 탭 화면 신설, 하단 탭바 연결
3. `feat(frontend)`: 전체 메뉴 화면 신설, 하단 탭바 연결

## 다음

  도메인이 생기면(이체결과 조회, 계좌 개설 등 이미 있는 라우트부터)
  해당 항목을 `Link`로 바꾸면 된다.

  기능이 필요해지면 그때 붙인다.
