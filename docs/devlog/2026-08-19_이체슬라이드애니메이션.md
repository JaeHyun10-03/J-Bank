# 2026-08-19 이체 화면 단계 전환 슬라이드 애니메이션

"다음 페이지로 넘어갈 때 그냥 전환돼서 부자연스럽다, 옆으로 슝
넘어가는 느낌이 있으면 좋겠다"는 요청. brainstorming 스킬로
bounded 분류, 짧게 설계·승인 받고 진행.

## 구조 확인

`app/accounts/[accountId]/transfer/page.tsx`는 실제 라우팅이
아니라 `accountStep`/`phoneStep` 같은 로컬 state로 완전히 다른
`return` 블록(각각 `<MobileScreen>`)을 그리는 구조다. 즉 단계가
바뀌면 React가 이전 트리를 버리고 새 트리를 마운트한다 — 애니메이션
트리거용 `key`를 따로 안 줘도 마운트 시점에 자연히 재생된다.

## 구현

새 의존성 없이 이미 설치돼 있던 `tw-animate-css`(shadcn 계열
패키지, `globals.css`에서 이미 import 중)의 `animate-in
slide-in-from-right` 유틸을 그대로 씀. 4개 단계 `<MobileScreen>`
className에 `animate-in slide-in-from-right fade-in duration-250`
추가.

퇴장(이전 화면이 왼쪽으로 밀려나가며 사라지는) 애니메이션은
의도적으로 생략 — 두 화면을 동시에 마운트 유지하는 트랜지션
매니저가 필요해서 비용 대비 효과가 작다고 판단(ponytail 판단,
사용자 승인받음). 방향 구분(뒤로가기 시 반대 방향)도 없음, 항상
오른쪽에서 진입.

## 검증

Chrome으로 `/accounts/9/transfer` → 계좌 선택 → 금액 입력 단계
전환 확인, 최종 렌더링에 잔여 transform 없이 정상 정착하는 것 확인.
`npx tsc --noEmit`에 해당 파일 관련 신규 에러 없음.

## 놓친 부분: confirm·otp 라우트

`/transfer/page.tsx` 내부 단계에만 적용하고 끝냈더니, 사용자가
"이체 페이지에서 연속적으로 다 적용해야지, 페이지 하나만 적용하면
어떡하나"라고 지적. `/transfer/confirm`, `/transfer/otp`는
`transfer/page.tsx`의 로컬 state가 아니라 진짜 Next.js 라우트라서
같은 흐름인데 빠져 있었다. Next.js App Router도 라우트 전환마다
새 페이지 컴포넌트를 마운트하므로 같은 `animate-in
slide-in-from-right` 패턴이 그대로 통한다 — 별도 라우트 트랜지션
라이브러리 없이 두 파일 `<MobileScreen>`에 동일 className만 추가.

Chrome으로 계좌 선택 → 금액 입력 → "다음" → confirm 라우트 →
"보내기" → 완료 화면까지 전체 플로우를 다시 클릭해서 라우트
전환에서도 슬라이드가 걸리는 것 확인(OTP는 테스트 계좌라 스킵되고
바로 완료 화면으로 감, 코드는 otp/page.tsx에도 반영해둠).
