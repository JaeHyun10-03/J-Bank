## 핵심 설계 판단

문서 전체에서 반복해서 근거로 쓰이는 판단들이다.

**되돌리는 비용으로 우선순위를 가른다.** 나중에 바꿀 때 이미 쌓인 데이터나 이미 붙은 클라이언트를 건드려야 하는 항목은 처음부터 지키고, 그렇지 않은 항목은 측정 후에 손댄다. 락 획득 순서·금액 타입·API 응답 계약은 앞쪽이고, 인덱스·캐시·커넥션 풀은 뒤쪽이다. 구현계획 7절.

**원장은 확정된 금전 이동만 담는다.** 2차 인증 대기 중인 금액은 원장을 건드리지 않고 계좌의 지급정지 금액으로만 관리한다. 그래서 취소된 거래가 정합성 대사를 깨뜨리지 않는다. ERD 2.2절, 요구사항명세서 FR-TXN-002.

**규제 접근이 막힌 구간만 대체한다.** 실명확인, 고액현금거래 보고, 전자서명은 감독당국 승인을 받은 사업자만 접속할 수 있다. 처리 절차와 데이터 구조는 실제 규정대로 설계하고 접근 불가 구간만 목업으로 바꿨다. 요구사항명세서 7.1절, 인프라아키텍처 13절.

**단일 애플리케이션 안에서 도메인 경계를 지킨다.** 상품·계좌·원장은 하나의 DB 트랜잭션에 참여하고, 패키지 의존 방향은 ArchUnit으로 검증한다.

| 도구 | 버전 |

### 최초 세팅

```bash
scripts/bootstrap.sh
```

도구 버전 확인, 프론트엔드 의존성 설치, 로컬 인프라(core 프로파일) 기동까지 한 번에 한다.

### 로컬 실행

```bash
# 인프라: PostgreSQL 16 + Redis 7
scripts/dev.sh core

# 백엔드
cd apps/jbank-api
./gradlew bootRun --args='--spring.profiles.active=local'
# http://localhost:8080/actuator/health
# http://localhost:8080/swagger-ui.html

# 프론트엔드
cd apps/frontend
npm run dev
# http://localhost:3000
```

관측 스택(Prometheus/Grafana/Loki)이 필요하면 프로파일을 더한다.

```bash
scripts/dev.sh core observability
```

전부 동시에 띄우는 단축 명령은 두지 않는다. 성능 측정 조건이 매주 달라지는 것을 막기 위해서다(`infra/compose/docker-compose.yml` 프로파일 구성, `10_J-Bank_폴더구조.md` 7절).

인프라를 내리려면 `scripts/clean.sh`.

## 상품·계약 트랜잭션

상품 API와 시드는 `jbank-api`에서 제공한다. 가입 계약·초기 납입금 출금·거래 원장은 하나의 서비스 트랜잭션으로 커밋하거나 롤백한다. 만기 이자 입금과 계약 만기 전환도 같은 배치 청크 트랜잭션에서 처리한다.

기존 DB의 Flyway 체크섬 검증을 위해 V1~V15는 수정하거나 삭제하지 않는다. V16은 계약의 계좌 필수 제약과 ACTIVE/MATURED/TERMINATED 상태 제약을 적용한다. 호환되지 않는 기존 계약이 있으면 마이그레이션을 중단한다. 계좌가 비어 있거나 그 외 상태인 계약의 실제 거래 결과를 확인한 후 정리해야 하며, 마이그레이션이 금전 처리 결과를 추정하거나 데이터를 삭제하지 않는다.

## DB 정리

적용된 Flyway 이력의 체크섬은 유지한다. V17은 더 이상 사용하지 않는 로그 알림 대기 테이블을 삭제하며 거래 원장과 감사 로그는 보존한다.
